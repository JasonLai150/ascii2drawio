# ascii2drawio

A CLI tool that converts ASCII / Unicode box-drawing diagrams (the kind LLMs commonly emit) into draw.io-importable XML. Single-file Python prototype today; LLM repair pass planned next.

## Goal

Take input like:

```
┌─────────┐         ┌─────────┐
│  Alpha  │────────>│  Beta   │
└─────────┘         └─────────┘
     │                   │
     │                   ↓
     │              ┌─────────┐
     └─────────────>│  Gamma  │
                    └─────────┘
```

…and produce a `.drawio` file that opens in draw.io / diagrams.net with the boxes in the same spatial positions the LLM chose, edges connecting them, arrowheads in the right direction, and any inline edge labels attached.

## Why mxGraph XML and not Mermaid

Mermaid would be cheaper to emit (draw.io supports Mermaid import natively), but the whole point of preserving an ASCII diagram is preserving the LLM's chosen layout. Mermaid recomputes layout. mxGraph XML lets us pin each node at `(col × CHAR_W, row × CHAR_H)` so the imported diagram looks like the ASCII source, not a re-laid-out version.

## Approach: deterministic primary, LLM repair fallback

Decided early against pure-LLM extraction (slow, costly, non-reproducible) and against actor-critic loops (this is a parsing task with ground truth — a critic mostly re-derives what the actor produced). The hybrid plan:

1. **Deterministic parser** handles the 80% — clean Unicode/ASCII boxes, traced edges, arrowheads, mid-line labels. Fast, free, debuggable.
2. **Confidence signal** flags localized failures (orphan-edge cells, unclaimed corners, edges-missing-endpoint).
3. **LLM repair pass** (planned) looks at the flagged regions only, returns missing nodes/edges as JSON, merges into the graph before XML emit.
4. **No critic loop.** A deterministic validator on the LLM output catches obvious errors more cheaply than a second LLM pass.

## What's built today

`ascii2drawio.py` (single file, ~350 lines) — strict-mode parser:

- `Grid` — pads input to a rectangular char grid.
- `find_rectangles()` — detects closed rectangles starting from `┌` / `+` corners. Captures interior text as label.
- `find_edges()` — flood-fills along line glyphs (`─│┌┐└┘+-|`), bridges gaps where labels interrupt a line (`── label ──`), resolves endpoints to nodes, infers direction from arrowhead glyphs (`→ ← ↑ ↓ > < v ^`).
- `emit_drawio()` — wraps nodes/edges in mxGraph XML at pixel coords scaled by `CHAR_W=9`, `CHAR_H=18`.
- CLI: `python3 ascii2drawio.py input.txt -o out.drawio` with `--annotate` (debug colorization) and `--report` (stderr summary).

Three hand-written examples in `examples/` (simple, labeled, ascii).

## Self-test corpus and audit harness

`examples/sysdesign/` — 20 system-design-interview architecture diagrams generated by an Explore subagent (URL shortener, rate limiter, news feed, web crawler, distributed cache, video streaming, ride sharing, payment processing, distributed storage, task queue, load balancer, CDN hierarchy, online auction, stock trading, log aggregation, API gateway, saga microservices, etc.).

`scripts/audit.py` — runs the parser on every fixture and reports per-file: nodes detected, edges detected, orphan-edge cells, unclassified line cells, edges missing an endpoint, XML validity. Aggregates totals.

`scripts/diagnose_orphans.py` — for each file with unclaimed top-left corners, reports *why* `_try_close_rect` rejected each candidate (top edge hit a non-corner, right wall fell off grid, bottom edge had a gap, etc.).

## Past experiments and findings

### Round 1 — initial parser (strict mode only)

20/20 fixtures produced well-formed XML, 0 unclassified line cells, 0 edges missing endpoints. **But 762 orphan-edge cells across 10 of 20 files.** Concentrated in `16-online-auction` (123) and `20-saga-microservices` (188).

Diagnosis: two root causes, neither was a parser bug.

1. **LLM emits column-misaligned boxes** (~14 cases) — top corner at column N, walls at column N±1 in the middle rows. Visually identical, character-misaligned. `_try_close_rect` correctly bailed, no false positives.
2. **Tee glyphs (`┬ ┴ ├ ┤ ┼`) on rectangle borders** (~7 cases) — boxes sharing a border with an edge that tees in. `TR_CORNERS` / `BL_CORNERS` only contained `┐ + └ +`, so a `┬` mid-edge broke rectangle closure.

### Round 2 — parser tightening

Implemented:

- `H_BORDER` / `V_BORDER` sets that accept tees as continuation of horizontal/vertical runs (`┬ ┴ ┼` horizontal, `├ ┤ ┼` vertical).
- ±1 column tolerance on right walls and BL/BR corner positions in `_try_close_rect`. Walks the right wall checking `c1`, `c1-1`, `c1+1` per row; falls back to BR-corner-at-c1±1 if BR isn't at c1 exactly.
- Per-row left/right wall tracking so interior label extraction respects the actual wall column on each row.

Results: orphan cells **762 → 389 (-49%)**. Nodes detected 161 → 170, edges 130 → 137. All 20 still produce valid XML, no regressions on the original 3 fixtures.

Remaining failures (after Round 2):

1. **±2 column drift** (1 case in `13-task-queue` — Result Store box, corners at col 83, walls at col 81). Pushing tolerance to ±2 risks false positives, deferred.
2. **`┌─┐ ─┬─ ─┤` constructs** (~6 cases) — these are *edge-lines starting with* `┌`, not rectangles. Parser correctly rejects them; `diagnose_orphans` flags them as "top edge hit non-corner ┬/┤" but they're not actually missed boxes.
3. **`┼` mid-rectangle** (~3 cases) — genuinely ambiguous; treated as line glyph by mistake when it's also part of a border.

Decision: stop deterministic tightening. Going further trades false negatives for false positives. Remaining 389 orphan cells are exactly the kind of localized, well-bounded ambiguity an LLM repair pass should handle cheaply.

## Current direction: LLM repair integration

The plan:

1. **Detect orphan regions.** After `find_rectangles` / `find_edges`, scan `consumed[r][c] == ("orphan-edge", -1)` cells, cluster contiguous ones into bounding boxes. Each cluster is one "region needing repair."
2. **Build a localized prompt per region.** Send Claude:
   - The list of detected nodes (id, bounds, label) — full set, so Claude can refer to them by id.
   - The orphan region as a sub-grid with a few rows/cols of context around it.
   - Schema-constrained output: `{repairs: [{type: "node"|"edge", ...}]}`.
3. **Validate and merge.** Deterministic validator checks: every referenced node id exists, edges have ≥2 endpoints, no overlap with already-claimed cells. Reject malformed responses; don't re-prompt.
4. **Re-emit XML** with merged graph.

Design decisions still open:

- **One LLM call total or one per region?** One total is cheaper (cache the system prompt + node list, change only the orphan region) but lets the model conflate regions. One per region is cleaner but pays the per-call overhead.
- **Schema strict mode?** `strict: true` on the tool definition guarantees valid JSON shape, worth using.
- **Model choice?** Probably Haiku 4.5 — this is a localized parsing task, not an open-ended reasoning task. Opus would be overkill.
- **Caching strategy?** The 20 fixtures share zero prefix, but for a *single* user's diagram the system prompt + node list could cache across multiple region calls.

## Constraints / non-goals (current)

- **Strict mode only** for now — every node must be a closed rectangle. Loose mode (label-only nodes, like `Map view → marker → renderer`) was sketched as a `--loose` flag but not implemented; planned to land alongside or after LLM repair.
- **Edge-row labels only** — labels embedded *in* an edge line are captured (`── every 30 seconds ──`); labels floating *above* or *below* an edge line (the `request` / `response` case in `examples/labeled.txt`) are not. Could be a future heuristic or could fall out of LLM repair.
- **No `--llm` flag wiring yet** — the LLM repair pass design above is not implemented; it's the immediate next step.
